# Ryugi 独立服务分享验证

验证日期：2026-11-25（Asia/Shanghai）。版本：插件专用 `ryugi-artifacts 1.108.1`。

## 结论

在同一台机器上，可以将工件复制到另一项目目录，由独立部署的同版本 Ryugi 服务加载。目标服务提供原有展示应用、内容运行时、评论接口和 WebSocket，无需转换成静态分享站。

本次完成文件、HTTP、WebSocket 和持久化验证；没有使用浏览器，没有验证视觉渲染、按钮交互或公网访问。

## 实验设置

- 通过会话 Ryugi 工具创建两个专用测试工件：`artboard/share-deployment-probe`、`document/share-deployment-probe`。
- 画板包含 HTML、相对路径 CSS、SVG 图片、`ryugi-icon` 和原生按钮脚本；文档包含原生文本、图片和指向该画板的引用。
- 将完整 Ryugi 安装包复制到临时目录，直接运行其中的服务端程序。未使用系统 launcher、CLI 安装器或 Agent hook。
- 仅复制这两个工件目录，保留 `.artifact-id`、文档块 ID 和文件结构。未复制源项目的服务状态、账号凭据或 `.state`。
- 目标服务使用独立的项目目录、状态目录、socket，主端口为 27619，画板内容端口为 27629。Cloud 地址指向不可用的本地端口，关闭更新检查；未向 Cloud 发布。
- 通过目标服务的 `/api/hub/projects` 注册上传目录。临时移走源工件后执行完整验证，源服务没有提供这些源文件。

## 部署含义与边界

服务器预装匹配版本的 Ryugi 后，发布器可以上传工件目录并注册项目。服务端生成目标地址和内容前缀，无需将应用重写成静态 viewer。

仍需处理：公网域名/HTTPS、两个服务端口的地址映射、上传流程、服务持久运行和版本管理。依赖作者本机 API 或开发服务器的页面不会因复制目录自动可用。后续更新不能直接删除或覆盖目标评论及服务状态；本次仅验证更新 canvas.json 保留评论。

本次未验证 Linux 部署、外网客户端、复杂业务工件、评论回流、账号、访问隔离或服务端再分发许可。临时服务已停止，测试目录已清理，源测试工件在恢复后清理；插件实现未修改。
